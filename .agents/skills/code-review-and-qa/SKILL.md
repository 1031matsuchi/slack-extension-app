# コードレビュー・品質検証スキル (`code-review-and-qa`)

本リポジトリのルール（`AGENTS.md`）およびマルチBot相乗りアーキテクチャの安全性基準に照らし合わせ、機械的なしきい値でコードを監査します。

## 監査手順と実行ゲート

以下の4つのゲートを順番に実行し、1つでも不合格があれば修正を行ってから再検証してください。

### Gate 1: スタイル・絶対ルールの機械的検査

1. **ケバブケース検査**:
   - `apps/`, `scripts/`, `tests/` 配下のすべてのファイル・ディレクトリ名がケバブケース（`[a-z0-9-.]`）であることを確認する。
2. **説明コメント充足検査**:
   - 初学者が処理内容や設計意図を理解できるよう、追加・変更した関数の責務や重要な処理（`ack()` の呼び出し理由、`try...catch` による例外隔離など）に適切な説明コメント（JSDocや `//` コメント）が記述されていることを確認する。
   - コメントが不足している場合は、初学者向けに補足コメントを追加するよう指摘する。

### Gate 2: マルチBot相乗り安全性（Fault Isolation）検査

1. **トークン未設定時のスキップ安全性**:
   - 各 `apps/<app-name>/index.js` の `initApp(env, options)` が、トークン未設定・空文字・`YOUR_*` プレースホルダーのときに例外を投げず `null` を返すことを確認する。
   - テスト環境（`env.NODE_ENV === 'test'`）で `tokenVerificationEnabled: false` が指定されていることを確認する。
2. **例外の隔離**:
   - すべてのリスナーコールバックが `try ... catch (error)` で囲まれ、`logger.error(error)` で処理されていることを確認する。
3. **秘密情報の漏洩防止**:
   - `xoxb-` や `xapp-` で始まる実トークンがコードや `.env.sample` に含まれていないことを確認する。

### Gate 3: Biome リンター＆フォーマッター検証（しきい値: エラー 0件）

```sh
npm run lint
```

- エラーやフォーマット差分が検出された場合は `npm run lint:fix` を実行し、再度 `npm run lint` が Exit Code 0 になることを確認する。

### Gate 4: 単体テスト実行検証（しきい値: Fail 0件）

```sh
npm test
```

- すべてのテストスイートがパスし、Unhandled Rejection が発生していないことを確認する。

## レビュー結果レポート形式（強制フォーマット）

レビューを求められた場合は、以下の表形式で監査結果を出力してください：

| 監査カテゴリ | 検査項目                               | 基準（しきい値） | 結果        | 詳細・指摘事項 |
| :----------- | :------------------------------------- | :--------------- | :---------- | :------------- |
| ファイル命名 | ケバブケース準拠                       | 違反 0件         | PASS / FAIL |                |
| コード規約   | 説明コメントの充足                     | 不足 0件         | PASS / FAIL |                |
| 相乗り安全性 | トークン未設定スキップ & `try...catch` | 未保護 0件       | PASS / FAIL |                |
| 静的解析     | `npm run lint` (Biome)                 | エラー 0件       | PASS / FAIL |                |
| 単体テスト   | `npm test` (`node:test`)               | 失敗 0件         | PASS / FAIL |                |
