# チーム別 開発進め方プラン（`docs/plans/`）

このディレクトリには、5 名の開発チーム（GAS 班・Bot 班・リーダー/リマインダー班）が **互いにコンフリクトせず、最初の 1 週間で安全に疎通させるための具体的な進め方** を班ごとにまとめています。

まずは自分の担当班のプランを開いて、Step 0 から順番に進めてください。

## 2. 全チーム共通の 1 週間ロードマップ

| 期間 | 共通マイルストーン | 狙い |
| :--- | :--- | :--- |
| **Day 1（キックオフ）** | 環境構築完了 ＋ 各班の未確定事項（TBD）を合意し要件定義書へ反映 | 「何を作るか」のズレを初日に解消する |
| **Day 1〜4（前半）** | **完全モック（`MOCK_GEMINI=true` / 固定ダミーデータ）で一気通貫の疎通** | API 制限やプロンプト調整で詰まらず、画面〜処理〜結果表示の骨格を最速で動かす |
| **Day 5〜7（後半）** | **開発用無料枠 API キー ＋ 完全な架空データで実連携検証** | プロンプト精度とテスト用 Google カレンダーへの登録・取得を検証する |

---

## 3. 全チーム絶対厳守ルール

> [!CAUTION]
> **開発用無料枠 API キーへの実データ入力は絶対禁止**  
> 開発用無料枠の Gemini API キー（請求先未設定プロジェクト）を使う検証では、**本物の学校年間行事予定 Excel や、生徒・教員の実名・個人情報を含む実データを絶対に入力しないでください**。検証には必ず完全な架空データのみを使用してください。

1. **`main` ブランチへの直接 push 禁止（GitHub Flow）**
   - 作業は必ずブランチを切って進めます（例：`git checkout -b feat/gas-passcode-ui`）。
   - 1 つの PR は小さく保ち、**ペア内でのバディチェック（動作確認・コード確認）** を行ってからリーダーへレビュー依頼します。
2. **担当ファイル境界の遵守（コンフリクト防止）**
   - 他班・他メンバーの担当ファイルを無断で編集しないでください。共通基盤（`lib/`, `prisma/`, `app.js`）の変更が必要な場合は必ずリーダーへ相談してください。
3. **秘密情報のコミット禁止**
   - `.env`、Slack トークン（`xoxb-`, `xapp-`）、Gemini API キー、Google サービスアカウント JSON キーは絶対に Git に含めないでください。
4. **詳細ルールの正本**
   - コーディング規約・DB 規約・完了ゲートは [`AGENTS.md`](../../AGENTS.md) を参照してください。
