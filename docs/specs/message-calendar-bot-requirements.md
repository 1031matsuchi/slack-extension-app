# 個別要件定義書：Slack 予定登録 Bot（`message-calendar-bot`）

- **対象サブシステム**: `apps/message-calendar-bot/`
- **親文書**: [`REQUIREMENTS.md`](REQUIREMENTS.md)

---

## 1. 目的と位置づけ

Slack の日常的なやり取りの中で投稿されたイベント告知や締め切り情報に対し、利用者がリアクションを付与することで AI（Gemini）が予定を抽出し、ワークスペースごとに設定された共有 Google カレンダーへ登録・管理する Slack Bot です。

---

## 2. 確定している方針・要件（MVP：Must）

| 要件ID | 項目 | 確定内容 |
| :--- | :--- | :--- |
| **MC-01** | **起動トリガー** | Slack 投稿に対する `📅` / `📆` リアクション付与（`reaction_added`）を起点とする。 |
| **MC-02** | **AI モデル方針** | **`gemini-3.5-flash-lite`** を採用（環境変数 `GEMINI_MODEL` で切替可能）。日常開発・テスト時は `MOCK_GEMINI=true` で動作させる。 |
| **MC-03** | **登録先カレンダー選択** | 静的ファイル（`config/calendars.json`）管理は不採用とし、**ワークスペース単位で DB 管理されたカレンダー** を対象に、Slack 上のボタン等で登録先を選択できること。 |
| **MC-04** | **重複登録防止・完了表示** | 同一メッセージからの重複登録を防止し、登録完了時には元メッセージへ `✅` スタンプを付与すること。 |
| **MC-05** | **Slack 上での予定削除** | Bot 経由で登録した予定について、**登録者本人またはワークスペース管理者（Primary Owner）** が Slack 上の操作から予定を削除できること（MVP に含む）。 |

---

## 3. 次期フェーズ要件（Should / Could）

- **行事キーワード類似予定検知・削除依頼ワークフロー（旧 `REQ-08`）**:
  - 類似する行事予定がすでに登録されていないかキーワードで検知し、先行登録者へ削除依頼を送るワークフローは MVP 対象外とし、次期フェーズで検討する。

## 4. 未確定事項（TBD：担当者が詳細確定後に追記）

以下の詳細仕様は Bot 班（メンバー C・D）の要件確定後に決定します。

1. **複数カレンダーの DB 物理設計**: 既存 `workspace_calendar_configs` テーブルへの JSON カラム追加 vs 新規テーブル（`workspace_calendars` 等）作成の選定。
2. **Gemini プロンプト・Structured Outputs スキーマ**: 抽出必須項目（終日予定、場所、説明文等）と曖昧な日時（「来週金曜」等）の補完ルール。
3. **UI・文面詳細**: 登録先カレンダー選択ボタンのレイアウト、登録完了／削除完了時のスレッド返信フォーマット、エラー時のメッセージ文言。
4. **重複判定キーの具体仕様**: メッセージ識別子（チャンネル ID + `ts` 等）の保持方法と削除後の再登録許可可否。
